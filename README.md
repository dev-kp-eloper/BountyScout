# BountyScout

**BountyScout** automatically scans configured sources for new bounty opportunities and opens a GitHub issue for each one. This repository powers the [BountyScout GitHub Action](/.github/workflows/bounty-scout.yml) that runs on a schedule.

## How it works
1. The Python script `scout_bounties.py` fetches the latest bounty alerts from the external API.
2. It loads `seen_bounties.json` to determine which alerts have already been processed.
3. For each new alert, it creates a GitHub issue in this repository.
4. After successful issue creation, the alert ID is added to `seen_bounties.json`.

## Setup

### Required secrets
| Name | Description |
|------|-------------|
| `GITHUB_TOKEN` | Token with `repo` scope (automatically provided by GitHub Actions). |
| `BOUNTY_API_URL` | URL of the endpoint that returns the latest bounty alerts (JSON array). |

### Environment variables (set in the workflow)
- `GITHUB_REPOSITORY_OWNER` – automatically set by GitHub Actions.
- `GITHUB_REPOSITORY` – automatically set by GitHub Actions.

## Development

```bash
# Install dependencies
pip install -r requirements.txt

# Run locally (ensure the required env vars are set)
python scout_bounties.py
```

The script will create issues via the GitHub REST API. When running locally, you must provide a personal access token with `repo` permissions via the `GITHUB_TOKEN` environment variable.

## Testing

The script includes robust error handling and will not duplicate issues. To test the detection logic, you can temporarily modify `fetch_bounties` to return a static list of mock bounties.
