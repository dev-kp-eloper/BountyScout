### Please re-state the problem that we are trying to solve in this issue.

In [`dev-kp-eloper/BountyScout`](https://github.com/dev-kp-eloper/BountyScout), Issue #1675 (`🎯 Bounty Alert: 13 New Opportunityies found`) was automatically generated by the hourly scan workflow running [`scout_bounties.py`](file:///scout_bounties.py). This issue highlights four critical production defects in the automated bounty scraping, filtering, and notification pipeline:

1. **Grammatical & Pluralization Defect in Issue Titles and Notifications (`Opportunityies`)**:
   - When the scanner detects more than one bounty (`len(new_bounties) > 1`), it incorrectly appends `'ies'` to the base word `'Opportunity'`, resulting in the misspelled token `"Opportunityies"` in both the issue title (`🎯 Bounty Alert: 13 New Opportunityies found`) and the notification bodies (`Found 13 new opportunityies:`).
2. **Recursive Bot Feedback Loop & Tracker Poisoning (False-Positive Alert Items)**:
   - Item #2 in Issue #1675 is `[🎯 Bounty Alert: 12 New Opportunityies found](https://github.com/freedom-winds/BountyScout/issues/1329)`, which is an alert issue created by another fork/clone of `BountyScout`.
   - The candidate triage function ([`is_clean_candidate()`](file:///scout_bounties.py#L61)) only checks whether an issue is a PR, assigned, overcrowded (>25 comments), or contains spam keywords. It completely lacks checks for bot authors (`user.type == "Bot"` or `[bot]`), tracker alert titles, tracker repository names, or internal labels (`bounty-alert`). This causes `BountyScout` instances across GitHub to index each other's alerts in an infinite, self-referential noise loop.
3. **Broken Markdown Link Delimiters & Telegram Notification Parser Failures**:
   - In [`scout_bounties.py#L190`](file:///scout_bounties.py#L190), raw issue titles are directly interpolated into Markdown link syntax: `#### {idx}. [{b['title']}]({b['url']})`.
   - Real-world bounty issues commonly use bracketed prefixes (e.g. Item #1: `[[find opt-out] SalesTech, LLC...]`, Item #3: `[[Bug]: Unauthenticated email relay...]`, Item #10: `[[RegisterSec] UK pentester...]`, Item #13: `[[wildcard] Cap-clipped reslices...]`).
   - The unescaped inner brackets prematurely close the Markdown link text `[`...`]`, producing corrupted Markdown rendering on GitHub. Furthermore, in Telegram (`parse_mode="Markdown"`), unescaped square brackets and special formatting tokens (`*`, `_`, `` ` ``) in titles trigger HTTP 400 `Bad Request: can't parse entities`, causing Telegram notifications to fail silently.
4. **Unbounded Storage Growth & Git Commit Bloat in `seen_bounties.json`**:
   - The state file [`seen_bounties.json`](file:///seen_bounties.json) is an unbounded flat JSON array that grows on every run. It has already ballooned to ~867 KB with tens of thousands of URLs.
   - Because the GitHub Actions workflow commits and pushes [`seen_bounties.json`](file:///seen_bounties.json) every hour, committing an ever-larger 1MB JSON file adds tens of megabytes of Git packfile bloat each day, degrading runner checkout performance and risking repository size quota limits.

### What changes do you think we should make in order to solve the problem?

We will make the following code modifications in [`scout_bounties.py`](file:///scout_bounties.py):

1. **Fix Pluralization Grammar**:
   Introduce a clean helper or dynamic conditional formatting:
   `noun = "opportunities" if len(new_bounties) != 1 else "opportunity"`
   `noun_title = "Opportunities" if len(new_bounties) != 1 else "Opportunity"`

2. **Harden [`is_clean_candidate()`](file:///scout_bounties.py#L61) Against Tracker Loops & Bots**:
   - Filter out bot authors (`user.get("type") == "Bot"` or `login.endswith("[bot]")`).
   - Filter out issue titles matching `^🎯\s*Bounty Alert` or `^📋.*open bounties`.
   - Filter out issues from known tracker repositories (`repo_fullname` or repository path ending with `/BountyScout` / `/bounty-watcher`).
   - Filter out issues bearing tracker labels like `bounty-alert`.

3. **Sanitize Markdown Links & Telegram Payloads**:
   - Escape square brackets (`[` and `]`) in `b['title']` when constructing Markdown links `[safe_title](url)`.
   - Switch Telegram messages to HTML formatting (`parse_mode="HTML"`) with `html.escape()`, ensuring robust entity parsing regardless of special characters in titles.

4. **Implement Bounded LRU/Window Retention in [`save_seen_bounties()`](file:///scout_bounties.py#L34)**:
   - Cap the stored list to a maximum of 5,000 URLs (`MAX_SEEN_URLS = 5000`), preserving the most recently recorded entries and preventing infinite state/git bloat.

### What alternative solutions did you explore? (Optional)

1. **Third-Party Inflection Library (e.g., `inflect` or `pattern.text`)**:
   - *Exploration*: Using an external NLP library to handle irregular English plurals.
   - *Comparison*: `scout_bounties.py` is intentionally lightweight with zero external pip dependencies (standard Python library only). Adding `pip install inflect` complicates the GitHub Actions runner setup without material benefit, since the noun here is strictly "opportunity" / "opportunities".
2. **Real-time Query-level Exclusions (e.g., `-repo:dev-kp-eloper/BountyScout -author:app/github-actions`)**:
   - *Exploration*: Appending negation qualifiers directly to the GitHub Search query strings.
   - *Comparison*: GitHub API query syntax limits total query length and boolean operators. Moreover, qualifiers like `-repo:...` cannot capture all user forks of BountyScout. Post-retrieval triage in `is_clean_candidate()` reliably catches all bot authors, forks, and tracker patterns without consuming search qualifier budget.
3. **Telegram MarkdownV2 Escaping vs. HTML**:
   - *Exploration*: Using `parse_mode="MarkdownV2"` and escaping all 18 reserved characters (`_`, `*`, `[`, `]`, `(`, `)`, `~`, `` ` ``, `>`, `#`, `+`, `-`, `=`, `|`, `{`, `}`, `.`, `!`).
   - *Comparison*: MarkdownV2 regex escaping is fragile and prone to breakage whenever user titles contain complex punctuation or emojis. Switching to standard `parse_mode="HTML"` with `html.escape()` provides 100% deterministic entity escaping.
